## 1. 디자인 방향

### 1.1 제품의 역할

타로티카는 일상의 고민을 AI 타로 리딩과 공감하는 문장으로 돌아보도록 돕는 모바일 서비스다. 정해진 미래를 예언하거나 중요한 결정을 대신하지 않는다.

### 1.2 핵심 원칙

1. **한 화면에 하나의 명확한 목표**: 무료 카드 뽑기, 질문 작성, 카드 선택처럼 현재 해야 할 일을 분명하게 보여준다.
2. **읽기 쉬운 정보 위계**: 제목 → 핵심 설명 → 콘텐츠 → 주요 행동 순서로 배치한다.
3. **비용과 상태를 먼저 설명**: 크레딧 사용량, 차감 시점, 무료 여부를 행동 전에 알린다.
4. **차분하고 친근한 경험**: 넉넉한 여백, 중립색 바탕, 블루 액션 컬러를 사용한다.
5. **타로의 상징은 콘텐츠에 집중**: 달·태양·별과 네이비·크림·골드 카드 아트워크로 정체성을 표현한다. 화면 전체를 장식적인 점술 테마로 채우지 않는다.
6. **사용자의 판단과 사생활 존중**: 불안을 자극하는 단정적 문구를 피하고, 개인 질문은 공유 이미지에서 기본 제외한다.

## 2. 기준과 적용 범위

### 2.1 값의 구분

- **확인값**: 2026-10-23 현재 Figma 레이어에서 확인한 색상, 글꼴, 치수, 문구.
- **권장 규칙**: 반응형 동작, 접근성, 상태 처리 등 구현·확장 시 적용할 기준. 현재 화면 전체에 구현되었다는 뜻은 아니다.
- 아래 토큰 이름은 문서용 의미 이름이다. Figma 변수, 텍스트 스타일, 재사용 컴포넌트가 등록되어 있다고 가정하지 않는다.

### 2.2 정책 충돌 처리

현재 유저플로우·와이어프레임과 상세 기능명세 사이에 수치 차이가 있다. 이번 디자인은 **상세 기능명세서 F-01~F-04를 우선 적용**했다. 기존 기획 문서는 이 변경에서 수정하지 않는다.

| 항목 | 이번 디자인 기준 | 이전 자료의 상충 내용 |
| --- | --- | --- |
| 심층 리딩 비용 | 1회 10크레딧 | 일부 자료 3크레딧 |
| 차감 시점 | 카드 3장 선택 후 리딩 요청 확정 시 | 질문 다음 단계에서 선차감하는 흐름 |
| 출석 일일 보상 | 2크레딧 | 일부 자료 1크레딧 |
| 7일 연속 출석 | 일일 보상 외 추가 10크레딧 | 일부 자료에 누락 |
| 구매 패키지 | 30 / 100 / 300크레딧 | 다른 수량·보너스 구성 |
| 가격 | 3,300 / 9,900 / 26,400원 | 일부 자료의 다른 가격 |

정식 개발 전 유저플로우·와이어프레임의 해당 수치를 함께 정합화해야 한다. 법적 환불 기간, 보너스 지급, 서비스 성과를 임의로 확정하지 않는다.

### 3.3 사용 규칙

- 화면별 주요 행동은 하나의 명확한 위계로 강조한다. 동일 위계의 강한 CTA를 남발하지 않는다.
- 선택 상태는 색만 바꾸지 말고 체크, 선택 표시, 텍스트 등으로 함께 전달한다.
- 보조 텍스트·밝은 배경·블루 버튼의 텍스트 대비는 출시 전 별도 측정한다. 현재 팔레트가 모든 조합에서 접근성 기준을 통과했다고 보장하지 않는다.

## 4. 타이포그래피

### 4.1 서체 — 확인값

- 기본 한국어 UI: **Noto Sans KR**
- 사용 굵기: Regular 400 / Medium 500 / Bold 700
- 카드 아트워크 내부 일부 영문 장식: **Lora Regular**
- 장식용 영문 서체는 본문·가격·버튼·폼에 사용하지 않는다.

### 4.2 역할별 크기 — 확인값과 정리 기준

| 역할 | 현재 사용 크기 | 굵기 | 적용 |
| --- | --- | --- | --- |
| 페이지 핵심 제목 | 27~28px | 700 | 홈·질문·결과 헤드라인 |
| 핵심 조언 | 19px | 700 | 데일리 결과의 한 줄 조언 |
| 섹션 제목 | 18px | 700 | 상세 리딩·섹션 구분 |
| 컨트롤·소제목 | 16~17px | 700 중심 | 버튼·상단 바·폼 제목 |
| 주요 본문 | 15px | 400 중심 | 리딩과 설명 |
| 보조 본문 | 13~14px | 400/500 | 안내·기록 요약 |
| 메타·짧은 레이블 | 11~12px | 400/500/700 | 날짜·잔액 설명·보조 문구 |

- 여러 본문·제목에서 행간 약 **155%**, 자간 **0%**가 확인된다. 컨트롤 등 일부 텍스트는 자동 행간이다.
- 카드 썸네일 속 작은 장식 글자는 UI 본문 크기 기준에서 제외한다. 필수 카드명·방향·의미는 썸네일 밖에도 읽을 수 있는 텍스트로 제공한다.
- **권장**: 중요한 비용, 약관, 오류 안내를 작은 메타 텍스트에만 담지 않는다. 글자 확대 시 줄바꿈과 컨테이너 높이가 함께 늘어나야 한다.

## 5. 레이아웃과 간격

### 5.1 확인한 기준 치수

| 항목 | 현재 Figma 값 |
| --- | --- |
| 화면 기준 폭 | 412px |
| 본문 좌우 여백 | 24px |
| 기본 본문 사용 폭 | 364px |
| 상단 바 | 높이 56px, 좌우 여백 24px |
| 상태 표시줄 표현 | 높이 52px |
| 주요 버튼 | 높이 56px, 모서리 16px |
| 주요 안내 카드 | 모서리 22px, 내부 여백 18px인 사례 |
| 작은 컨테이너 모서리 | 8 / 12 / 16px 등 |
| 화면 외곽 표현 | 모서리 32px |
| 하단 탐색 전체 영역 | 높이 98px인 사례 |
| 홈 인디케이터 표현 | 높이 30px인 사례 |

레이아웃 간격에는 4, 6, 8, 10, 12, 14, 16, 24, 28px 등 여러 값이 사용되어 있다. 현재 결과물을 단일 8pt 그리드로 규격화한 것으로 설명하지 않는다.

### 5.2 구현 권장사항

- 412px는 디자인 기준 폭이지 모든 단말의 고정 폭이 아니다. 가로 폭에 맞춰 콘텐츠와 버튼을 유동적으로 확장한다.
- 상태 표시줄·시스템 내비게이션은 OS 안전 영역을 따른다. Figma의 52/30px 표현을 시스템 영역에 중복 적용하지 않는다.
- 긴 리딩 결과는 본문 스크롤로 제공한다. 화면을 축소해 한 뷰포트에 억지로 넣지 않는다.
- 하단 CTA를 고정할 경우 본문 마지막 내용이 가려지지 않도록 여유 공간을 확보한다.
- 질문 입력 중 키보드가 올라오면 입력 위치, 글자 수, 다음 행동이 접근 가능해야 한다.
- 주요 콘텐츠는 세로 흐름을 유지하고, 큰 글자 설정·작은 화면에서 제목·칩·가격이 충돌하지 않도록 재배치한다.

## 6. 공통 UI 규칙

### 6.1 버튼

- 주요 버튼: 블루 면, 명확한 행동 레이블, 확인된 높이 56px·모서리 16px.
- 보조 버튼: 주요 버튼보다 낮은 위계. 공유 화면에서 이미지 저장과 공유하기는 구분한다.
- 레이블 예: `오늘의 타로 무료로 뽑기`, `다음 · 카드 고르기`, `10크레딧으로 리딩 보기`, `2크레딧 받기`.
- 유료 확정 행동은 사용량 또는 금액을 행동 가까이에 표시한다.
- 로딩·비활성·오류 상태는 후속 디자인 및 구현 대상이다. 구현 시 중복 제출·중복 결제를 막고 원인을 알려준다.

### 6.2 칩과 선택 항목

- 질문 카테고리: 연애/결혼, 진로/이직, 금전/비즈니스, 인간관계, 학업/시험, 기타.
- 단일 선택 상태를 분명하게 표시하고 긴 한국어 레이블을 잘라내지 않는다.
- 보관함은 전체/오늘의 타로/심층 타로로 구분한다. 검색·추가 필터는 별도 요구사항 없이 구현 완료로 간주하지 않는다.

### 6.3 질문 입력

- 입력 조건: 10~300자. 실제 입력 문자열과 일치하는 글자 수 표시.
- 예시 질문: `최근 이직을 고민하고 있어요. 지금 회사에 남는 게 좋을까요, 새로운 기회를 찾는 게 좋을까요?`
- 현재 화면의 예시 카운터: `53 / 300`.
- 최소 길이에 미달하면 다음 행동을 제한하고 이유를 입력란 가까이에 안내한다.
- 이름·연락처 같은 개인정보 입력을 요구하지 않는다.
- 초과 입력, 유해 질문, 포커스·오류 상태의 시각 표현은 후속 정의 대상이다.

### 6.4 타로 카드

- 앞면·뒷면에 동일한 아트워크 언어를 사용한다. 네이비·크림·골드와 달·태양·별 모티프가 기준이다.
- 3장 스프레드의 순서는 **과거 → 현재 → 미래**로 고정한다.
- 카드명, 순서, 정방향/역방향을 색이나 그림만으로 전달하지 않는다.
- 데일리 예시: 태양, 정방향. 심층 예시: 전차 / 운명의 수레바퀴 / 별, 정방향.
- 78장의 전체 덱을 작은 터치 대상으로 한 화면에 밀집시키지 않는다. 선택 영역과 선택된 3장의 위치를 명확히 분리한다.

### 6.5 내비게이션

- 최상위 탭: 홈 / 보관함 / 상점.
- 선택 탭은 아이콘과 텍스트의 강조를 일치시킨다.
- 질문·카드 선택·결과 등의 하위 흐름은 뒤로가기와 단계 표시를 제공한다.
- 뒤로가기, 앱 이탈, 재진입 시 데이터 복구 동작은 구현 시 별도 정의한다.

### 6.6 공유 미리보기

- 결과 이미지 비율: **9:16**.
- 포함: 타로티카 브랜드, 선택 카드, 간단한 리딩 메시지.
- `내 질문 포함하기`는 기본 꺼짐. 옵션을 켜기 전에는 고민 원문을 이미지에 넣지 않는다.
- 저장·공유 실패와 앨범 권한 거부를 처리해야 한다. 실제 공유는 OS 공유 기능 연동 후 검증한다.
- 연결 대상이 없는 장식용 QR을 실제 다운로드 링크처럼 사용하지 않는다.

## 8. 화면별 핵심 규칙

### DG-01 홈

- 주요 행동은 하루 한 번 무료 카드 뽑기다. 심층 리딩과 출석은 보조 진입점이다.
- 무료 리딩은 크레딧을 사용하지 않는다. KST 자정에 참여 가능 횟수가 초기화되며 미사용 횟수는 이월되지 않는다.
- 현재 화면은 미참여 상태다. 참여 완료 후 재뽑기 방지·오늘의 결과 다시보기·다음 자정 안내 상태를 추가해야 한다.

### DG-02 데일리 결과

- 카드명·방향, 총운, 연애운, 금전운, 한 줄 조언을 제공한다.
- 결과는 자동 저장 정책을 따른다. 수동 저장을 하지 않아도 보관함에서 볼 수 있음을 알린다.
- 예시 날짜는 2026.10.23이며 다음 무료 참여는 10월 24일 00:00 KST다. 운영 시 날짜를 동적으로 표시한다.

### DG-03~05 심층 리딩

- 1단계 질문 작성 → 2단계 카드 선택 → 3단계 리딩 결과.
- 질문 작성과 카드 선택 중에는 비용을 차감하지 않는다. 3장 선택 후 리딩 요청을 확정할 때 10크레딧을 차감한다.
- 현재 카드 선택 화면은 3장 선택 완료 상태다. 미선택·1장·2장 상태는 추가 제작 대상이다.
- 결과는 종합 요약 → 과거·현재·미래 해석 → 작은 실천 제안 순으로 읽게 한다.
- AI 생성 실패 또는 15초 타임아웃 시 자동 환불 정책을 적용한다. 생성 대기·실패 화면은 아직 별도 제작되지 않았다.

### DG-06~07 보관함과 공유

- 기록은 최신순이며, 날짜·리딩 종류·질문 요약·카드 정보를 읽을 수 있게 표시한다.
- 삭제는 명확한 확인과 실패 복구가 필요하다. 현재 목록 화면에 모든 삭제 동작이 설계되었다고 가정하지 않는다.
- 개인 질문을 제외한 공유 미리보기로 시작한다. 미리보기와 실제 출력의 내용·비율을 일치시킨다.

### DG-08 상점

| 상품 | 가격 | 10크레딧 기준 심층 리딩 분량 |
| --- | --- | --- |
| 30크레딧 | 3,300원 | 3회 |
| 100크레딧 | 9,900원 | 10회 |
| 300크레딧 | 26,400원 | 30회 |

- 현재 선택 상품은 100크레딧이며 CTA도 `100크레딧 · 9,900원에 구매하기`로 일치한다.
- 무료 크레딧 우선 사용, 무료 유효기간 30일, 유료 유효기간 없음 규칙을 안내한다.
- 실제 구매 가능 횟수는 잔액 합산과 정책에 따라 달라질 수 있다. 위 횟수는 해당 패키지 자체의 분량이다.
- 결제 성공 문구와 잔액 갱신은 서버 영수증 검증이 끝난 뒤에만 표시한다.

### DG-09 출석

- 현재 예시는 1~5일차 완료, 오늘 6일차 미수령, 내일 7일차 예정 상태다.
- 오늘 수령 시 +2, 7일 연속 출석일에는 당일 +2에 추가 +10이다.
- 현재 잔액 5와 수령 후 잔액 7을 동시에 현재 상태로 표시하지 않는다.
- 출석 초기화는 KST 00:00 기준이다. 출석 중복 수령을 막는다.

## 9. 잔액과 상태 정합성

| 시점 | 총 잔액 | 무료 | 유료 |
| --- | --- | --- | --- |
| 홈·질문 작성·카드 선택 | 15 | 5 | 10 |
| 무료 데일리 결과 | 15 | 5 | 10 |
| 심층 리딩 10 사용 후 | 5 | 0 | 5 |
| 상점·출석 미수령 예시 | 5 | 0 | 5 |
| 오늘 출석 보상 수령 후 — 후속 상태 | 7 | 2 | 5 |

같은 세션에서는 질문, 선택 카드, 날짜, 사용 비용, 공유 메시지를 일관되게 유지한다. 심층 리딩 실패 시 해당 사용 건의 차감분을 복구하며, 이미 처리된 요청에 중복 환불·중복 지급하지 않는다.

## 10. UX 라이팅

### 10.1 말투

- 짧고 이해하기 쉬운 해요체를 사용한다.
- 사용자의 감정을 단정하거나 평가하지 않는다.
- 행동과 결과를 구체적으로 쓴다. `확인` 대신 가능한 경우 `카드 고르기`, `2크레딧 받기`처럼 쓴다.
- 결과는 가능성과 성찰을 제안한다. 확정적 예언, 투자·의료·법률 판단을 대신하는 표현을 피한다.

| 피할 표현 | 권장 표현 |
| --- | --- |
| 이직하면 반드시 성공합니다 | 내가 원하는 일의 기준부터 적어보면 좋겠어요 |
| 결제해야 운명을 알 수 있어요 | 심층 리딩은 한 번에 10크레딧을 사용해요 |
| 오류가 발생했습니다 | 리딩을 만들지 못했어요. 사용한 10크레딧은 돌려드렸어요 |
| 개인정보를 자세히 입력하세요 | 이름이나 연락처 같은 개인정보는 적지 않아도 괜찮아요 |

오류 예시의 환불 완료 문구는 실제 환불 확인 후에만 사용한다. 복구 중이면 `크레딧을 돌려드리는 중이에요`처럼 현재 상태를 알린다.

### 10.2 결과 고지

현재 화면의 안내 취지를 유지한다.

> 타로는 정해진 미래가 아닌, 나를 돌아보는 힌트예요.

> AI가 카드의 상징을 바탕으로 정리한 이야기예요. 중요한 결정은 나의 상황과 마음을 함께 살펴주세요.

## 11. 접근성·반응형 권장 기준

아래는 출시 전 검증할 기준이며, 현재 화면 전체가 통과했다는 결과가 아니다.

- 일반 텍스트 대비 4.5:1 이상, 큰 텍스트 3:1 이상을 목표로 실제 전경/배경 조합을 측정한다.
- 상호작용 경계·상태 인지에 필요한 비텍스트 요소도 적절한 대비를 확인한다.
- 터치 영역은 iOS 44pt / Android 48dp 이상을 목표로 한다. 그림 크기와 실제 터치 영역을 구분한다.
- 색만으로 선택·오류·출석 완료를 전달하지 않는다.
- 모든 카드·뒤로가기·탭·토글에 읽을 수 있는 접근성 이름과 상태를 제공한다.
- 질문 카운터, 로딩, 결제·환불 상태를 스크린리더에서 이해할 수 있게 안내한다.
- 글자 확대, 좁은 화면, 긴 카테고리·카드명, 키보드 표시 상태를 검증한다.
- 셔플·뒤집기·타이핑 연출을 구현한다면 동작 줄이기를 존중하고, 연출만으로 필수 정보를 전달하지 않는다.
