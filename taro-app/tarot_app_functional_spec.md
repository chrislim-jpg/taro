- **문서 ID**: SPEC-TAROT-2026-01

- **버전**: v1.0
- **표준 규격**: 서비스 기획 프로세스 표준 SOP (P- → F- → n- → S- 추적성 준수)

## 1. 개요 및 추적성 구조

본 기능명세서는 상위 PRD(`P-01` ~ `P-04`)의 요구사항을 구체적인 시스템 동작 규칙, 비즈니스 로직, 데이터 입출력, 예외 처리로 구체화한 문서입니다. 본 문서의 `F-` ID는 하위 유저플로우(`n-`) 및 와이어프레임(`S-`)과의 추적성을 유지합니다.

| PRD ID | 기능명세서 ID (F-ID) | 기능명 | 주요 정의 범위 |
| :--- | :--- | :--- | :--- |
| **P-01** | **F-01** | 일일 무료 타로 (1장 데일리 카드) | 자정 리셋 규칙, 1장 카드 셔플/선택, 일일 운세 생성 로직, 푸시 알림 |
| **P-02** | **F-02** | AI 심층 타로 리딩 | 카테고리/질문 유효성 검사, 3장 카드 스프레드(과거/현재/미래), LLM 프롬프트/스트리밍 연동, 크레딧 선차감 및 환불 처리 |
| **P-03** | **F-03** | 리딩 결과 보관함 및 공유 | 리딩 기록 DB 저장/페이징 조회, 결과 카드 렌더링(이미지 캐싱), SNS/OS 공유 모달 및 이미지 저장 |
| **P-04** | **F-04** | 포인트 및 결제 시스템 | 크레딧 잔액 트랜잭션 원자성, 출석 체크 출석부 규칙, IAP 결제 영수증 검증, 에러/환불 예외 로직 |

## 2. 세부 기능 명세

### F-01: 일일 무료 타로 (Daily Free Tarot)
- **상위 PRD**: `P-01`
- **목적**: 매일 로그인 유저에게 부담 없는 1장 카드의 데일리 운세와 조언을 제공하여 DAU 및 리텐션 향상.

#### 2.1 비즈니스 로직 및 동작 규칙
1. **리셋 기준**:
   - 매일 한국 표준시(KST) 기준 자정(`00:00:00`)에 무료 참여 횟수가 1회로 초기화됨.
   - 당일 사용하지 않은 무료 횟수는 이월되지 않고 소멸함.
2. **참여 상태 구분**:
   - `UNAVAILABLE_YET`: 오늘 이미 참여 완료함 (당일 재참여 불가, 다음 자정까지 남은 시간 타이머 표시).
   - `AVAILABLE`: 오늘 참여 가능 상태.
3. **카드 선택 및 셔플 로직**:
   - 78장 메이저/마이너 타로 덱 중에서 서버 측 Secure Random 알고리즘으로 1장을 무작위 추첨.
   - 카드 정방향(Upright) / 역방향(Reversed) 확률은 각각 50%로 처리.
4. **결과 생성 및 렌더링**:
   - 카드의 키워드, 오늘의 총운, 연애운, 금전운, 오늘의 한 줄 조언을 템플릿 형태로 1.5초 내 즉시 출력.

#### 2.2 데이터 입출력 명세
- **입력**: User ID, 카테고리(선택사항, 기본값: 오늘의 종합운)
- **출력**: Card ID, Card Name, Orientation(UPRIGHT/REVERSED), Image URL, Interpretation Title, Summary Content, Actionable Advice
- **유효성 검사**: User ID의 당일 `daily_tarot_logs` 내역 존재 여부 검증 (DB UNIQUE constraint: `user_id` + `date`).

#### 2.3 예외 처리 및 에러 코드
- `E0101` (이미 참여함): 자정 이전 재요청 시 "오늘의 데일리 타로를 이미 확인하셨습니다. 내일 다시 찾아주세요!" 팝업 노출.
- `E0102` (네트워크 장애): 카드 선택 중 통신 끊김 시 서버에 선택 기록이 저장되었다면 재접속 시 해당 결과 화면으로 자동 복구.

### F-02: AI 심층 타로 리딩 (Deep AI Tarot Reading)
- **상위 PRD**: `P-02`
- **목적**: 사용자의 구체적 고민을 AI가 다각도로 분석하고 3장 스프레드(과거-현재-미래)를 기반으로 깊이 있는 맞춤 해석 제공.

#### 2.1 비즈니스 로직 및 동작 규칙
1. **카테고리 및 질문 입력**:
   - 카테고리 옵션: `연애/결혼`, `진로/이직`, `금전/비즈니스`, `인간관계`, `학업/시험`, `기타`
   - 질문 입력란: 최소 10자 ~ 최대 300자 입력 제한. (Placeholder: "현재 겪고 계신 상황과 궁금한 점을 솔직하게 적어주세요.")
2. **카드 셔플 및 3장 스프레드 인터랙션**:
   - 카드 덱 셔플 애니메이션(2.0초) 진행.
   - 펼쳐진 카드 중 사용자가 직접 3장의 카드를 순서대로 클릭/선택.
   - 슬롯 위치: 1st (과거/원인), 2nd (현재/상황), 3rd (미래/조언).
3. **재화 차감 규칙 (선차감 & 원자성)**:
   - 심층 리딩 1회 시 10 크레딧 차감.
   - '카드 3장 선택 완료' 시점에 크레딧 선차감 수행.
   - AI 응답 생성 실패(Timeout 15초 초과 또는 API Error) 시 트랜잭션 롤백 및 크레딧 자동 환불.
4. **AI 프롬프트 연동 및 스트리밍 처리**:
   - System Prompt: 전문 타로 공감 상담사 페르소나 적용 (따뜻하고 공감하는 어조, 구체적 액션 플랜 제시).
   - User Input: `{category}`, `{question}`, `{card1_info}`, `{card2_info}`, `{card3_info}`
   - LLM 응답을 Server-Sent Events(SSE) 또는 WebSocket 스트리밍으로 수신하여 화면에 텍스트 타자 효과(Typing effect)로 렌더링.

#### 2.2 데이터 입출력 명세
- **입력**: User ID, Category Code, Question Text (10~300자), Selected Card IDs [3], Card Orientations [3]
- **출력**: Reading Session ID, Overall Summary, Section 1 (과거 해석), Section 2 (현재 해석), Section 3 (미래 해석), Final Advice Text, Lucky Item/Color

#### 2.3 예외 처리 및 에러 코드
- `E0201` (질문 길이 미달/초과): 10자 미만 입력 시 "고민 내용을 최소 10자 이상 작성해 주세요." 토스트 메시지.
- `E0202` (크레딧 부족): 잔액 < 10 크레딧인 경우 "크레딧이 부족합니다. 충전 페이지로 이동하시겠습니까?" 모달 띄움.
- `E0203` (AI 응답 생성 실패 / 타임아웃): 15초 내 AI 응답 불개시 시 "AI 타로 마스터와 연결이 고르지 않습니다. 사용된 크레딧은 즉시 환불되었습니다." 알림 및 롤백.
- `E0204` (비속어 및 유해 질문): 욕설/유해어 필터링 진입 시 "올바른 질문을 입력해 주세요." 안내 및 차단.

### F-03: 리딩 결과 보관함 및 공유 (History & Social Share)
- **상위 PRD**: `P-03`
- **목적**: 과거의 타로 리딩 결과를 언제든 다시 열람하고, 미려한 결과 카드로 제작하여 인스타그램/카카오톡 등으로 공유 유도.

#### 2.1 비즈니스 로직 및 동작 규칙
1. **리딩 결과 보관 (History DB)**:
   - F-01(일일 타로) 및 F-02(심층 타로) 완료 즉시 `user_tarot_readings` 테이블에 결과 자동 저장.
   - 보관함 목록은 최신순 정렬, 카테고리별 필터링 제공.
   - 보관 내역 개별 삭제 기능 제공.
2. **결과 카드 이미지 생성 (Shareable Card Generator)**:
   - 뽑은 타로 카드 이미지 + 질문 핵심 요약 + 타로티카 브랜드 로고가 조합된 9:16 비율(인스타 스토리 최적화) 이미지 카드 동적 생성.
   - 이미지 생성 시 클라이언트 캔버스(Canvas API) 또는 서버 렌더링 활용.
3. **SNS 및 OS 단말 공유**:
   - iOS/Android Native Share Sheet 연동 (인스타그램 스토리 공유, 카카오톡 딥링크 공유, 이미지 앨범 저장).

#### 2.2 데이터 입출력 명세
- **입력**: Reading Session ID, Share Target (INSTAGRAM / KAKAOTALK / SAVE_ALBUM)
- **출력**: Generated Image File (PNG/JPG), Deep Link URL (`tarotica://reading?id={session_id}`)

#### 2.3 예외 처리 및 에러 코드
- `E0301` (저장 권한 거부): 단말기 앨범 접근 권한 없을 시 "설정에서 앨범 접근 권한을 허용해 주세요." 안내.
- `E0302` (삭제 실패): 네트워크 불량으로 삭제 실패 시 복구 트랜잭션 처리.

### F-04: 포인트 및 결제 시스템 (Points & In-App Purchase)
- **상위 PRD**: `P-04`
- **목적**: 무료 체리픽 유저의 정착과 유료 크레딧 결제 전환을 위한 출석 보상 및 인앱 결제(IAP) 체계 구축.

#### 2.1 비즈니스 로직 및 동작 규칙
1. **재화 구조**:
   - `무료 크레딧 (Bonus Credit)`: 출석 체크, 이벤트 등으로 획득 (유효기간 30일).
   - `유료 크레딧 (Paid Credit)`: 인앱 결제로 구매 (유효기간 없음).
   - 사용 순서: 차감 시 무료 크레딧 우선 차감 후 유료 크레딧 차감.
2. **출석 체크 보상**:
   - 매일 앱 접속 시 출석 버튼 활성화.
   - 출석 성공 시 2 크레딧 즉시 지급. 연속 7일 출석 시 추가 10 크레딧 지급.
3. **인앱 결제 (IAP) 및 영수증 검증**:
   - Apple App Store (IAP) 및 Google Play Billing 서비스 연동.
   - 상품 패키지: 30 크레딧(\3,300), 100 크레딧(\9,900), 300 크레딧(\26,400).
   - 결제 완료 후 **서버 대 서버(Server-to-Server) 영수증 검증** 성공 시에만 크레딧 지급.

#### 2.2 데이터 입출력 명세
- **입력**: User ID, Product ID, Purchase Token / Receipt Data
- **출력**: Updated Balance (Bonus Credit, Paid Credit), Transaction ID, Timestamp

#### 2.3 예외 처리 및 에러 코드
- `E0401` (영수증 검증 실패): 어뷰징/유효하지 않은 영수증 시 크레딧 지급 거절 및 로그 기록.
- `E0402` (미지급 건 재검증): 결제 완료 후 네트워크 차단 시 앱 재실행 시 미완료 트랜잭션 자동 검증 및 크레딧 지급 (Pending Transaction Queue).
